## Summary

Vote: **Yes.**

This proposal funds the **Technical Steering Committee (TSC)** for 12 months, covering:
- **WP1:** Community-facing technical coordination (events, technical reports, expert attendance)
- **WP2:** Protocol governance and evolution (Parameter Committee, CIP editors, Hard Fork Working Group)
- **WP3:** Independent technical review program pilot

The TSC performs a function that Cardano genuinely needs: **independent technical governance**. The Parameter Committee's evidence-based parameter recommendations, the CIP editorial process, and hard fork coordination are foundational infrastructure for a decentralized blockchain. Without them, protocol evolution becomes either stagnant or captured by single vendors.

The ask — ₳1.19M — is modest and proportionate. The technical review program (WP3) is especially valuable: it directly addresses the information asymmetry that makes DRep voting difficult.

However, this proposal has the same structural issues I flag in every Intersect-administered ask: self-funding, thin budget detail, no ADA volatility policy, and invisible milestones. It is also **contingent on the main Intersect MBO budget passing** — if that fails, this may not execute even if ratified. These concerns temper my enthusiasm but do not block a Yes vote at this scale.

## What This Proposal Gets Right

### 1. Independent Parameter Committee Is Critical Infrastructure

The Parameter Committee provides **evidence-based advice on protocol settings**, with benchmarking studies conducted **independently of node vendors and implementation teams**. This is not a trivial function. In ecosystems where parameter decisions are influenced by vested interests, the protocol drifts toward designs that benefit specific suppliers.

Cardano's Parameter Committee, funded through this proposal, ensures that:
- Protocol parameter changes are grounded in objective analysis
- No single node vendor can unduly influence protocol direction
- DReps receive independent technical input for governance votes

This is a **public service** with clear durability and accountability mechanisms.

### 2. CIP Editors and Hard Fork Working Group Are Essential

The CIP (Cardano Improvement Proposal) process is how research and innovation translate into protocol changes. Without funded editors and coordination:
- CIPs stall in review queues
- The improvement pipeline clogs
- Community contributors lose incentive to propose changes

The Hard Fork Working Group ensures that protocol upgrades are **coordinated safely and effectively** — a function demonstrated during past network upgrades and critical during incidents like the November 2025 chain partition.

### 3. Technical Review Program Directly Supports DReps

WP3 — the independent technical review pilot — is arguably the most valuable component of this proposal. DReps face an information asymmetry problem: they must vote on complex technical proposals without the expertise to evaluate them independently.

A funded technical review program, with:
- Formal conflict-of-interest provisions
- Published recusals
- Open reviewer selection against documented criteria

...directly addresses this gap. This is **institutional capacity** that improves the quality of governance decisions across the entire ecosystem.

### 4. Unspent Funds Returned to Treasury

The proposal commits to "full expenditure accounting and any unspent funds returned to the Cardano treasury." This is a meaningful fiscal discipline signal, especially compared to proposals that treat the full ask as a use-it-or-lose-it budget.

### 5. External Audit by Appold

Same as the main Intersect proposal — independent audit and assurance by Appold. Post-hoc, but better than nothing.

### 6. Strategic Alignment Is Genuine

The TSC's work cross-cuts all five Cardano 2030 pillars, with the strongest alignment to:
- **Pillar 1 (Infrastructure):** Parameter recommendations, hard fork coordination, CIP pipeline
- **Pillar 3 (Governance):** Technical review for DReps, transparent evidence-based decisions
- **Pillar 5 (Sustainability):** Fiscal discipline, independent oversight of core infrastructure spending

This is not forced alignment — it is the natural consequence of the TSC's actual functions.

### 7. Modest Amount for Critical Function

₳1,193,000 for 12 months of technical governance infrastructure is proportionate. Broken down:
- WP1 (community coordination): ₳256K
- WP2 (protocol governance): ₳832K
- WP3 (technical review): ₳105K

WP2 is the largest component, which is correct — the Parameter Committee, CIP editors, and Hard Fork Working Group are the core functions. WP3 at ₳105K is a lean pilot, which is appropriate for a new program.

## Concerns (Not Blocking, But Noted)

### 1. Self-Funding Pattern

Intersect is both the applicant and the administrator. This structural conflict is present here, just as it is in the main Intersect Ops proposal. The difference is scale: ₳1.19M is not ₳25.4M, and the functions are more specific and externally verifiable.

### 2. Budget Detail Is Thin

| Work Package | Amount |
|---|---|
| WP1 — Community-Facing Technical Coordination | ₳256,000 |
| WP2 — Protocol Governance and Evolution | ₳832,000 |
| WP3 — Technical Review | ₳105,000 |

Three line items for ₳1.19M. Better than one line item for ₳18.8M, but still lacking:
- How many Parameter Committee members are compensated? At what level?
- What does CIP editorial work cost? Is this per-CIP or retainer?
- How many technical reports are commissioned under WP1? At what cost?
- How many technical reviews does WP3 fund? What is the per-review cost?

### 3. No ADA Volatility Policy

Same gap as every Intersect proposal. For a 12-month operational budget:
- No conversion assumption
- No excess-return rule
- No underfunding contingency

Given the modest amount, this is manageable. But it is still a gap.

### 4. Milestones Not Visible in Public Metadata

The proposal references "milestone-based drawdowns" but does not publish specific milestones. DReps cannot verify what "done" looks like for each work package without more detail.

### 5. Contingent on Main Intersect Budget

The proposal explicitly states: "The execution of the work packages outlined in the proposal is contingent on the IntersectMBO budget proposal's approval."

This means if the main Intersect Ops proposal (₳25.4M) fails, this proposal may not execute even if ratified. This creates a dependency that voters should understand: a Yes vote here does not guarantee execution if the main budget fails.

### 6. Deepens Intersect Dependency

Every Treasury dollar that flows through Intersect deepens the ecosystem's dependency on a single organization. The TSC's functions are valuable, but the concentration of governance infrastructure in one entity creates long-term risk. I would like to see a plan for diversifying or rotating these functions across multiple entities.

I apply a **contextual override** for the following reasons:

1. **The function is uniquely valuable and hard to replicate.** Independent parameter advice and CIP editorial coordination are not services the market provides spontaneously.
2. **The amount is modest.** At ₳1.19M, the risk of misuse or poor value is contained.

4. **The technical review program addresses a real DRep pain point.** Information asymmetry in governance is a structural problem; this is a credible attempt to address it.

## Final Statement

Vote: **Yes.**

The Technical Steering Committee performs governance infrastructure functions that Cardano genuinely needs: independent parameter advice, CIP editorial coordination, hard fork planning, and — most valuably — a technical review program that helps DReps make informed votes.

The concerns I raise — self-funding structure, thin budget detail, no ADA volatility policy, and deepening Intersect dependency — are real and would be more severe at a larger amount. At ₳1.19M with specific, verifiable functions, they are manageable concerns, not blockers.

I distinguish this proposal sharply from the main Intersect Ops ask (₳25.4M, Abstain). The TSC has a clear remit, modest price, and externally verifiable outputs. The main Intersect proposal is a massive, opaque operational catch-all. Scale and specificity matter.

If the TSC resubmits in future with more granular budget detail, an ADA volatility policy, and a diversification roadmap, I would evaluate it even more favorably. As it stands, the public value justifies the vote.
